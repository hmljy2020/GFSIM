# Mesh 节点

每个节点有一对本地注入/交付端口，并与每个物理邻居连接一对单向队列。角节点、其余边界节点、内部节点分别有 2、3、4 个邻居。队列由 [MeshBench](MeshBench.md) 持有，节点没有子对象，构建容量为 0。

## 从接线读到转发

以节点 0 发往节点 1 为例，生成的 [MeshBench.cpp](MeshBench.cpp) 把同一个 `link_0_to_1` 传给节点 0 的东向输出和节点 1 的西向输入。`link_1_to_0` 负责反方向。两个节点的构造函数分别对这些指针调用 `BindOutput` 和 `BindInput`。

顶层实例化同一个 `MeshNode` 类 40 次。该类直接继承 `gfsim::SimModule`，构造函数接收节点编号以及本地、西、东、北、南五对具名队列指针。编号用于命名和 XY 路由，每个实例独立保存仲裁状态。[节点声明](MeshNode.h)

边界方向传入一对 `nullptr`，构造函数仅绑定非空队列。节点 0 的西、北两个方向为空，东、南方向连接实际邻居。输入检查和余量采样会跳过空指针。

本地输入赢得东向输出且该输出有余量时，`Work()` 依次执行 `packet = localIn_->Front()`、`eastOut_->Write(packet)` 和 `localIn_->Pop()`。节点 1 下一拍通过 `westIn_` 看到同一个包。所有实例共用这份构造、五个生命周期方法和展开的仲裁逻辑。[节点实现](MeshNode.cpp)

## 单拍转发

1. 查看各输入的可见队首。`Route(node, destination)` 根据实例的节点编号，优先沿 X，再沿 Y 选择下一跳。坐标重合时选择本地交付。
2. 每个输出独立仲裁请求它的输入。轮询顺序为本地、西、东、北、南，跳过不存在的方向。复位时从本地输入开始，只有成功授予后才把游标移到获准输入的下一个位置。每个输入和输出每拍最多参与一次转发，彼此独立的输出可以同时获准。
3. 使用拍初记录的输出余量判定能否发送。写入成功后弹出输入，节点间转发将同一包的跳数加一，并标记进展。阻塞时保留队首身份、内容和仲裁游标。
4. 拍末顶层推进所有物理队列，节点在 `Xfer()` 采样下一拍余量。下游本拍腾出的槽位在下一拍可用。复位时先清空顶层队列，再采样各输出并清零转发计数。

Debug 日志的 `forward` 和 `blocked` 阶段定位实际输出队列。`ReportStat()` 汇报该节点自复位以来成功送入邻居链路的次数。开启 trace 后，每次成功转发在 `mesh/node_N` 泳道产生一拍的 `forward` 事件，附带目标队列名。示例 CTest 用两个输入争用同一输出，验证授予顺序、满队列、阻塞时的包身份和恢复后的 XY 路径。
